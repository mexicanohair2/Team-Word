# Team Word — QQCross

Team Word — командная игра, в которой все участники совместно угадывают одно слово. Игровой клиент публикуется отдельно, но использует общие профили и серверные комнаты QQCross.

## Запуск

Игра — статическое приложение GitHub Pages. Локальная установка не требуется.

- **Одиночная игра:** работает локально и не требует авторизации. Два простых бота делают попытки с задержками и видят только открытые буквы и историю.
- **Мультиплеер:** вход выполняется с теми же почтой и паролем, что и в QQCross. Новый аккаунт не создаётся. После входа можно создать комнату либо подключиться по коду.

Из-за изоляции хранилища браузера между разными GitHub Pages адресами сессию нужно открыть отдельно в основном QQCross и в этой игре. Учетная запись при этом остаётся общей.

## Серверный контракт

Общие данные хранятся в проекте Supabase QQCross:
- `auth.users` и `profiles` — единая авторизация, ник и аватар;
- `qq_party_rooms` и `qq_party_players` — одна система комнат;
- `qq_party_secrets` и `private.qq_party_word_bank` — недоступный клиенту секретный ответ;
- `qq_party_events` — общие игровые действия.

Используемые RPC:
- `qq_party_create_room`, `qq_party_join_room`, `qq_party_get_room`;
- `qq_party_start_team_word`, `qq_party_team_guess`, `qq_party_tick_team_word`;
- `qq_party_leave_room`.

Сервер выбирает секретное слово из закрытого словаря. Параметры словаря, длины и ник, переданные клиентом, не определяют ответ и личность участника. Сервер проверяет длину, повторы и права комнаты. Каждая команда может отправлять догадки одновременно; раскрытие очередной буквы определяется серверным временем — 15 секунд.

Только подтверждённые неанонимные аккаунты с профилем QQCross могут создать или занять сетевое место. Гостевые профили и боты не имеют доступа к сетевым RPC.

## Проверка

`npm test` запускает Node.js unit-тесты для словаря, нормализации, раскрытия букв, оценки повторяющихся символов и поведения бота. GitHub Actions выполняет тесты перед публикацией Pages.

Реальную работу нескольких устройств необходимо отдельно подтвердить двумя независимыми аккаунтами QQCross после публикации. Unit-тесты не заменяют этот сетевой тест.

## GitHub Pages

Перед первым запуском включи Pages для репозитория:

1. Открой [Settings → Pages](https://github.com/mexicanohair2/Team-Word/settings/pages).
2. В разделе **Build and deployment** выбери **Source: GitHub Actions**.
3. Открой вкладку [Actions](https://github.com/mexicanohair2/Team-Word/actions) и повтори workflow **Test and deploy**.

Workflow сперва запускает `node --check app.js` и `node --test`; публикация выполняется только после успешного тестового задания. Сейчас автоматические тесты проходят. GitHub блокирует создание Pages site из workflow-токена, пока источник Pages не выбран в настройках репозитория.
